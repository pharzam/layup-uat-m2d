## Facts as collected

1. `S01-stack` go — by operator; source https://github.com/pharzam/layup-uat-m2d/issues/1#issuecomment-6173934710; the question: Which technology stack does the target use? Give a stack of the catalog of LAYUP, for example go.
2. `Q-001` Flags may be combined. Each flag selects its count; with several flags, tally prints the selected counts in the fixed order lines, words, characters. With no flag it prints all three. — by idea-owner; source https://github.com/pharzam/layup-uat-m2d/issues/1#issuecomment-6173919895; the question: May flags be combined (e.g. `-l -w` prints lines and words), or does each flag mean that count alone, and what happens when several are given?
3. `Q-002` A fixed order: lines, then words, then characters, whatever the order of the flags on the command line. — by idea-owner; source https://github.com/pharzam/layup-uat-m2d/issues/1#issuecomment-6173919895; the question: In what order are the selected counts printed: a fixed order (lines, words, characters) or the order the flags appear on the command line?
4. `Q-003` The row for standard input has no name: it ends after the counts. The name `-` is not accepted as standard input: tally treats it as a file named `-`. — by idea-owner; source https://github.com/pharzam/layup-uat-m2d/issues/1#issuecomment-6173919895; the question: What name, if any, is printed in the row for standard input, and is `-` accepted as a file name meaning standard input?
5. `Q-004` The total row is the sum of the counts of the files that were counted without an error, followed by the word `total`, in the layout of the other rows. A file that cannot be read, or is not valid UTF-8, adds nothing to the total. — by idea-owner; source https://github.com/pharzam/layup-uat-m2d/issues/1#issuecomment-6173919895; the question: What does the total row contain: the summed counts followed by the word `total`, and does it sum only the files that were counted without error?
6. `Q-005` No. A file that is not valid UTF-8 is skipped entirely, like an unreadable file: no row, no share of the total, a message on standard error with its name, and the exit code 1 at the end. — by idea-owner; source https://github.com/pharzam/layup-uat-m2d/issues/1#issuecomment-6173919895; the question: Does a file that is not valid UTF-8 still get a row and a share of the total (counting what it can), or is it skipped entirely like an unreadable file?
7. `Q-006` A file is not text exactly when it is not valid UTF-8 (rule 6). A directory is an unreadable file: tally prints a message on standard error with its name and the reason, adds no row, and ends with the exit code 1. — by idea-owner; source https://github.com/pharzam/layup-uat-m2d/issues/1#issuecomment-6173919895; the question: How is a file that is "not text" recognised: is it exactly a file that is not valid UTF-8 (rule 6), and what does tally do when given a directory?
8. `Q-007` A carriage return before a line feed is part of the line and is counted as a character, like any other code point. An empty file has zero lines, zero words and zero characters. — by idea-owner; source https://github.com/pharzam/layup-uat-m2d/issues/1#issuecomment-6173919895; the question: Is a carriage return before a line feed (CRLF) part of the line and counted as a character, and does an empty file count zero lines?
9. `Q-008` The reference is any computer with 4 cores and a solid-state disk, with the file already in the cache of the operating system, for a file of 10 MiB of ASCII text with lines of about 80 characters. The time is the elapsed time of the whole process, from its start to its exit. — by idea-owner; source https://github.com/pharzam/layup-uat-m2d/issues/1#issuecomment-6173919895; the question: Which reference machine (CPU model and speed, storage, warm or cold file cache) and which file content (ASCII, multi-byte, line lengths) define the 2-second target, and is the time the whole process or only the counting?
10. `Q-009` Yes: the limit is the peak heap during the run, not the heap at the end. It is measured by sampling the heap in use (`runtime.ReadMemStats`, `HeapAlloc`) every 10 milliseconds during the count and taking the largest value. — by idea-owner; source https://github.com/pharzam/layup-uat-m2d/issues/1#issuecomment-6173919895; the question: Is the limit on peak heap during the run rather than heap at the end (which a garbage collection can make small), and how is the peak measured?
11. `Q-010` Yes. tally reads each file in fixed buffers of 64 KiB and handles a UTF-8 sequence, and the detection of invalid UTF-8, across the boundary of two buffers; it never reads a whole file into memory. — by idea-owner; source https://github.com/pharzam/layup-uat-m2d/issues/1#issuecomment-6173919895; the question: Is it accepted that this requires streaming in fixed buffers, with UTF-8 sequences and invalid-UTF-8 detection handled across buffer boundaries, rather than reading whole files?
12. `Q-011` The counting package is a package `count` of the same Go module, separate from the package `main` of the command. It holds the functions that count the lines, the words and the characters of a reader. The idea owner defines this boundary here. — by idea-owner; source https://github.com/pharzam/layup-uat-m2d/issues/1#issuecomment-6173919895; the question: There is no design naming a "counting package": which package boundary (separate from the command's main) is meant, and who defines it?
